# 任务清洗与运行目录规范

本文档定义 `tasks/` 下任务原型、执行运行目录和评测运行目录的标准结构，用于后续规范化清洗任务。核心目标是稳定地区分「执行方可见内容」「Judger 私有内容」「运行时产物」和「作者参考资产」，同时允许不同任务使用不同输出格式，例如 `.npz` 重建结果或 `.py` 脚本提交。

## 核心原则

- `tasks/` 保存任务原型，默认只读，不直接写入运行输出。
- 执行方只接触 public bundle，不接触 `evaluation/`、私有参考数据或 `std_code/`。
- Judger 读取 public bundle、执行方输出和 private evaluation bundle，并把结果写入运行目录。
- `outputs/`、日志、`judge_result.json` 属于一次运行实例，不属于任务原型。
- `envs/` 统一使用独立 `.venv`，每个任务环境单独安装，不依赖系统 Python 的全局第三方包。

## README 保真原则

`README.md` 是执行方理解任务的主要入口。清洗时默认应保留原 README 中除私有评测答案和隐藏参考结果描述之外的所有有用信息，不应为了统一模板而压缩、扩写或重排任务说明。

必须保留：

- 背景介绍、问题定义、数学模型、物理模型和术语解释。
- 输入数据来源、公开输入字段说明、参数含义和单位。
- 方法提示、算法建议、难点说明和参考文献。
- domain、keywords、difficulty 等任务元信息。
- 原 README 或参考实现中对关键算法路线的强提示，例如 `mPIE`、`GRAPPA`、Newton/FBS/FBP、centered FFT、regularization、momentum、物理初始化等。清洗器不得把高质量算法提示降级为更弱的通用提示，例如把 `mPIE` 简化成只推荐 `ePIE`。

必须删除或改写：

- 私有评测答案、隐藏参考结果，以及可直接定位隐藏答案的信息。
- `evaluation/data/`、`reference_outputs/`、私有 judge 数据路径。
- 会让执行方绕过求解过程直接读取答案的内容。

推荐做法：

- 所有任务都采用最小 README 改写策略，不区分科学重建类、BioDS、notebook query 或脚本提交类任务。
- 不追加统一模板、`Required Output`、`Evaluation`、`Environment` 或其他额外章节。
- 只做必要脱敏和公开路径改写，例如将原输入路径改为 `visible_data/cases/<case_id>/input_data/` 或 `visible_data/cases/<case_id>/params_data.json`。
- 对 BioDS、notebook query 或脚本提交类任务，可只将原 `queries.md` 标题改为 `Task description` 并拼接 CoT。
- 输出格式、路径模板和必要的数据契约以 `output_schema.json` 为准；README 中原本已有的输出说明可以保留或做最小路径修正，但不强制新增。

## 总体目录

推荐项目根目录分为两个主要空间：

```text
project_root/
  tasks/
    conventional_ptychography/
      ...

  runs/
    run_20260511_0001/
      ...
```

`tasks/` 是任务库，保存可复用的任务原型。`runs/` 是运行库，每次执行或评测创建一个新的 run 目录。

## 任务原型目录

清洗后的任务原型建议使用以下结构：

```text
tasks/
  <task_id>/
    README.md
    requirements.txt
    output_schema.json
    task_manifest.json

    visible_data/
      cases.json
      cases/
        case_000/
          input_data/
            raw_data.npz
            positions.npy
          params_data.json

    evaluation/
      judge.py
      visualization.py            # 可选，按 src/notebooks 对齐可视化
      metrics.json
      test_cases.py               # 可选，脚本/assertion 类任务的私有 helper
      data/                       # 可选，仅在需要私有参考数据时存在
        cases/
          case_000/
            private_reference.npz

    envs/
      env_manifest.json
      runtime/
        .venv/
        uv.lock
        requirements.txt

    std_code/
      main.py
      src/
```

## 文件职责

| 路径 | 可见性 | 职责 |
| --- | --- | --- |
| `README.md` | 执行方可见 | 任务说明、输入说明、输出要求、方法提示。 |
| `requirements.txt` | 执行方可见 | 人类可读的依赖说明，也用于重建环境。 |
| `output_schema.json` | 执行方和 Judger 可见 | 约束输出路径、格式和公开提交契约；数组任务约束 key/shape/dtype，脚本任务约束脚本路径和变量契约。 |
| `task_manifest.json` | 平台/清洗器可见 | 声明任务分层、入口和运行时路径语义。 |
| `visible_data/` | 执行方可见 | 输入数据、参数、case 索引。 |
| `evaluation/` | 仅 Judger 可见 | judge 脚本、metric 配置、私有参考数据、私有测试用例和 helper。 |
| `envs/` | 按策略可见 | 实际 `.venv` 环境产物和环境入口说明。 |
| `std_code/` | 仅作者/清洗器可见 | 参考实现，不给执行方。 |

## public bundle

public bundle 是执行方可以看到的内容，通常从任务原型复制到 run 目录。

```text
README.md
requirements.txt
output_schema.json
visible_data/
envs/                  # 推荐复制，保证 run 自包含
```

执行方不应看到：

```text
evaluation/
evaluation/data/
std_code/
private_reference.npz
```

## private evaluation bundle

private evaluation bundle 是 Judger 私有内容：

```text
evaluation/
  judge.py
  metrics.json
  test_cases.py                 # 可选
  data/                         # 可选
    cases/
      case_000/
        private_reference.npz
```

它可以在评测前复制到 run 目录的 `judge/evaluation/`，也可以由 Judger 以只读方式挂载。

## author bundle

author bundle 用于任务作者、清洗器或 reference runner：

```text
std_code/
```

`std_code/` 不属于执行方输入，也不属于最终 Judger 必需输入。

## 执行运行目录

每次执行创建一个独立 run 目录：

```text
runs/
  run_20260511_0001/
    public/
      README.md
      requirements.txt
      output_schema.json
      visible_data/
      envs/

    workspace/
      solution.py
      solver.py
      user_notes.md

    outputs/
      case_000.npz              # 或 case_000.py，以 output_schema.json 为准

    logs/
      solver.stdout.log
      solver.stderr.log

    run_manifest.json
```

执行方通常可以访问：

```text
runs/<run_id>/public/
runs/<run_id>/workspace/
runs/<run_id>/outputs/
runs/<run_id>/logs/
```

执行方应将结果写到：

```text
runs/<run_id>/outputs/case_000.npz   # 数组任务示例
runs/<run_id>/outputs/case_000.py    # 脚本任务示例
```

具体文件名和后缀以 `output_schema.json` 的 `path_template` 为准。

不要把结果写回：

```text
tasks/<task_id>/outputs/
```

任务原型目录不应出现 `outputs/`。

## 评测运行目录

评测可以复用同一个 run 目录，并在其中创建 `judge/` 子目录：

```text
runs/
  run_20260511_0001/
    public/
      README.md
      requirements.txt
      output_schema.json
      visible_data/
      envs/

    outputs/
      case_000.npz              # 或 case_000.py，以 output_schema.json 为准

    judge/
      evaluation/
        judge.py
        metrics.json
        test_cases.py           # 可选
        data/                   # 可选
          cases/
            case_000/
              private_reference.npz

      judge_result.json
      logs/
        judge.stdout.log
        judge.stderr.log
```

Judger 读取：

```text
runs/<run_id>/public/
runs/<run_id>/outputs/
runs/<run_id>/judge/evaluation/
```

Judger 写入：

```text
runs/<run_id>/judge/judge_result.json
runs/<run_id>/judge/logs/
```

## 运行时复制流程

### 执行前

从任务原型复制 public bundle：

```text
tasks/<task_id>/README.md            -> runs/<run_id>/public/README.md
tasks/<task_id>/requirements.txt     -> runs/<run_id>/public/requirements.txt
tasks/<task_id>/output_schema.json   -> runs/<run_id>/public/output_schema.json
tasks/<task_id>/visible_data/        -> runs/<run_id>/public/visible_data/
tasks/<task_id>/envs/                -> runs/<run_id>/public/envs/
```

然后创建运行目录：

```text
runs/<run_id>/workspace/
runs/<run_id>/outputs/
runs/<run_id>/logs/
```

### 评测前

从任务原型复制 private evaluation bundle：

```text
tasks/<task_id>/evaluation/ -> runs/<run_id>/judge/evaluation/
```

然后创建：

```text
runs/<run_id>/judge/logs/
```

## envs 统一规范

`envs/` 表示实际环境产物，不只是依赖声明。所有任务统一使用独立 `.venv`，每个任务环境单独安装，不依赖系统 Python 的全局第三方包。

标准结构如下：

```text
envs/
  env_manifest.json
  runtime/
    .venv/                      # uv 或 venv 产物
    uv.lock                     # uv 项目保留；venv/pip 项目可为空或省略
    requirements.txt
```

要求：

- 每个任务有独立 `envs/runtime/.venv/`。
- 执行和评测都使用 `.venv` 内的 Python。
- 不通过 `PYTHONPATH` 引用 `site-packages`。
- 不依赖系统 Python 的全局第三方包。
- `requirements.txt` 用于说明和重建环境。
- `uv.lock` 用于 uv 锁定依赖；如果当前环境使用 `python -m venv` 创建，可以暂时没有 `uv.lock`，但 `env_manifest.json` 必须说明 manager。

### envs 复制策略

第一版建议直接复制 `tasks/<task_id>/envs/` 到 `runs/<run_id>/public/envs/`。

优点：

- run 目录自包含，便于复现。
- 执行和评测都可以使用相对路径。
- 不依赖任务原型目录继续存在。

缺点：

- 体积较大。
- 多次 run 会重复占用空间。

后续如果运行规模变大，可以改成共享环境引用，例如：

```json
{
  "env_manifest": "../../../tasks/<task_id>/envs/env_manifest.json",
  "runtime_venv": "../../../tasks/<task_id>/envs/runtime/.venv"
}
```

## env_manifest.json 规范

推荐格式：

```json
{
  "version": 1,
  "default_env": "runtime",
  "envs": {
    "runtime": {
      "manager": "uv",
      "kind": "venv",
      "path": "envs/runtime/.venv",
      "scope": ["solver", "judge"],
      "python": {
        "windows": "envs/runtime/.venv/Scripts/python.exe",
        "posix": "envs/runtime/.venv/bin/python"
      },
      "requirements": "envs/runtime/requirements.txt",
      "uv_lock": "envs/runtime/uv.lock"
    }
  }
}
```

如果使用 `python -m venv` 创建环境，`manager` 可以写为 `venv`。

## output_schema 语义

`output_schema.json` 约束执行方输出。输出路径应解释为相对于 run root，而不是相对于任务原型目录。

数组输出任务推荐格式：

```json
{
  "version": 1,
  "submission": {
    "base": "run_root",
    "path_template": "outputs/{case_id}.npz"
  },
  "format": "npz",
  "arrays": [
    {
      "key": "object",
      "required": true,
      "shape": [542, 542],
      "dtype": ["complex64", "complex128"],
      "description": "Reconstructed complex object."
    }
  ],
  "validation": {
    "finite_only": true,
    "allow_cast": false
  }
}
```

含义：

- `submission.base = run_root`：输出路径基于运行目录。
- `path_template = outputs/{case_id}.npz`：执行方应写入 `runs/<run_id>/outputs/case_000.npz`。
- `finite_only = true`：数组中不能包含 `NaN`、`Inf` 或 `-Inf`。
- `allow_cast = false`：实际 dtype 必须匹配允许列表，不允许隐式接受其他 dtype。

脚本提交任务推荐格式：

```json
{
  "version": 1,
  "format": "python_script",
  "path_template": "outputs/{case_id}.py",
  "execution": {
    "runner": "python",
    "contract": "submission script must define a pandas DataFrame named substitution_ratios"
  }
}
```

含义：

- `format = python_script`：提交物是可由 judge 执行或导入的 Python 脚本。
- `path_template = outputs/{case_id}.py`：执行方应写入 `runs/<run_id>/outputs/case_000.py`。
- `execution.contract`：公开说明脚本必须暴露的变量、类型和语义；私有断言仍应只放在 `evaluation/` 中。

## cases.json 规范

`visible_data/cases.json` 是 public case 索引。

```json
{
  "version": 1,
  "cases": [
    {
      "id": "case_000",
      "input_dir": "cases/case_000/input_data",
      "params": "cases/case_000/params_data.json",
      "expected_output": "outputs/case_000.npz",
      "description": "Single public input case."
    }
  ]
}
```

约定：

- `id` 必须唯一。
- `input_dir` 和 `params` 相对于 `visible_data/`。
- `expected_output` 相对于 run root，仅作为提示；最终以 `output_schema.json` 为准，可以是 `.npz`、`.py` 或其他受支持格式。
- 单组数据也必须包装为 `case_000`，避免 judge 只支持单 case。

## metrics.json 规范

`evaluation/metrics.json` 描述评测指标和反馈粒度。

```json
{
  "version": 1,
  "case_rule": "all_cases_pass",
  "metric_rule": "all_metrics_pass",
  "feedback": {
    "level": "metric_full"
  },
  "metrics": [
    {
      "name": "phase_ncc",
      "threshold": 0.878,
      "direction": "higher_is_better",
      "required": true
    },
    {
      "name": "phase_nrmse",
      "threshold": 0.0477,
      "direction": "lower_is_better",
      "required": true
    }
  ]
}
```

### feedback.level

`feedback.level` 由任务作者或平台管理员控制，执行方不应控制。Judger 调度器可以通过命令行参数临时覆盖。

推荐支持：

| level | 返回内容 |
| --- | --- |
| `overall_only` | 只返回总 pass/fail。 |
| `case_only` | 返回总 pass/fail 和每个 case 的 pass/fail。 |
| `metric_status` | 增加每个 metric 的 pass/fail。 |
| `metric_value` | 增加每个 metric 的当前输出值。 |
| `metric_full` | 增加阈值、方向和通过要求。 |

默认建议开发阶段使用 `metric_full`，隐藏评测或正式提交可以降级到 `case_only`。

## judge_result.json 规范

Judger 应输出机器可读结果：

```json
{
  "version": 1,
  "status": "pass",
  "summary": {
    "num_cases": 1,
    "num_passed_cases": 1,
    "num_failed_cases": 0
  },
  "feedback_level": "metric_full",
  "cases": [
    {
      "case_id": "case_000",
      "status": "pass",
      "reason": null,
      "metrics": [
        {
          "name": "phase_ncc",
          "status": "pass",
          "value": 0.91,
          "threshold": 0.878,
          "direction": "higher_is_better",
          "requirement": "value >= 0.878"
        }
      ]
    }
  ]
}
```

建议退出码：

| 退出码 | 含义 |
| --- | --- |
| `0` | 评测通过。 |
| `1` | 输出格式正确，但 metric 未通过，或 case 失败。 |
| `2` | judge 自身运行错误、配置错误或不可恢复异常。 |

## run_manifest.json 规范

执行 run 可以记录一个 manifest：

```json
{
  "version": 1,
  "task_id": "conventional_ptychography",
  "task_source": "../../tasks/conventional_ptychography",
  "phase": "solve",
  "public_dir": "public",
  "workspace_dir": "workspace",
  "output_dir": "outputs",
  "logs_dir": "logs",
  "cases": "public/visible_data/cases.json",
  "output_schema": "public/output_schema.json",
  "env": "public/envs/env_manifest.json"
}
```

评测后可以追加：

```json
{
  "judge_dir": "judge",
  "judge_result": "judge/judge_result.json"
}
```

## Judger 调用示例

假设当前目录是项目根目录，Windows 下可以运行：

```powershell
runs/run_20260511_0001/public/envs/runtime/.venv/Scripts/python.exe `
  runs/run_20260511_0001/judge/evaluation/judge.py `
  --submission runs/run_20260511_0001/outputs `
  --cases runs/run_20260511_0001/public/visible_data/cases.json `
  --schema runs/run_20260511_0001/public/output_schema.json `
  --metrics runs/run_20260511_0001/judge/evaluation/metrics.json `
  --eval-data runs/run_20260511_0001/judge/evaluation/data `
  --result runs/run_20260511_0001/judge/judge_result.json
```

Linux/macOS 下可以运行：

```bash
runs/run_20260511_0001/public/envs/runtime/.venv/bin/python \
  runs/run_20260511_0001/judge/evaluation/judge.py \
  --submission runs/run_20260511_0001/outputs \
  --cases runs/run_20260511_0001/public/visible_data/cases.json \
  --schema runs/run_20260511_0001/public/output_schema.json \
  --metrics runs/run_20260511_0001/judge/evaluation/metrics.json \
  --eval-data runs/run_20260511_0001/judge/evaluation/data \
  --result runs/run_20260511_0001/judge/judge_result.json
```

`--eval-data` 指向 Judger 私有数据目录。没有私有数据的任务也应保留该 CLI 参数兼容入口，judge 可以忽略它或接受不存在的空目录。

## 清洗流程建议

对用户提供的新任务，自动化清洗器应按以下流程处理：

1. 识别输入数据、私有评测数据、参考实现、README 和依赖文件；README 只做脱敏和必要公开路径修正，不应追加模板内容或摘要化重写。
2. 将单组或多组数据统一包装为 `visible_data/cases/case_xxx/`。
3. 生成 `visible_data/cases.json`。
4. 从任务说明、私有参考数据、测试用例或作者声明中生成 `output_schema.json`，并保留真实输出格式。
5. 将私有参考数据移入 `evaluation/data/cases/<case_id>/`；如果任务只需要私有断言或 helper，可以不创建 `evaluation/data/`。
6. 生成结构化 `evaluation/metrics.json`。
7. 生成或修复 `evaluation/judge.py`，确保支持多 case 和分层反馈；私有 helper 应相对 `Path(__file__).resolve().parent` 或 `--eval-data` 读取，不能从 `public/` 反推。
8. 生成 `task_manifest.json`，声明 public、private 和 author bundle。
9. 创建或引用 `envs/runtime/.venv` 独立环境，并生成 `env_manifest.json`。
10. 运行 reference output、标准答案脚本或临时样例输出，验证 judge 链路。
11. 检查 public bundle 泄漏，确保没有私有参考数据、reference output 或 `std_code/`。
12. 生成一次 run 目录，验证执行和评测都不写回任务原型。

## 清洗验收清单

- [ ] 任务原型目录没有 `outputs/`、`judge_result.json`、运行日志。
- [ ] `visible_data/cases.json` 存在，且所有 case 路径有效。
- [ ] `output_schema.json` 明确输出路径、格式和提交契约；数组任务包含 shape/dtype，脚本任务包含必须定义的变量名和类型。
- [ ] `evaluation/metrics.json` 明确 metric 名称、阈值、方向和反馈粒度。
- [ ] `evaluation/judge.py` 支持 CLI 参数，不依赖当前工作目录的隐式路径，也不从 public 路径推导私有 helper。
- [ ] public bundle 不包含私有参考数据、`evaluation/data/` 或 `std_code/`。
- [ ] Judger 能在 run 目录中读取 public、outputs 和 private evaluation 完成评测，即使任务没有 `evaluation/data/`。
- [ ] `judge_result.json` 至少包含总 pass/fail 和每个 case 的 pass/fail；建议每个 case 包含 `format.status` 和 `metrics[]`，避免 harness 反馈显示 `unknown`。
- [ ] `envs/env_manifest.json` 指向 `envs/runtime/.venv`，且执行和评测均使用该环境内的 Python。
- [ ] 使用临时 run 目录验证后，任务原型目录无新增运行产物。

## 命名约定

- 任务 ID 使用小写蛇形命名，例如 `conventional_ptychography`。
- case ID 使用 `case_000`、`case_001` 递增。
- 执行输出统一放在 `outputs/` 下，具体文件名和后缀以 `output_schema.json` 的 `path_template` 为准。
- Judger 结果统一命名为 `judge_result.json`。
- 日志文件建议使用 `solver.stdout.log`、`solver.stderr.log`、`judge.stdout.log`、`judge.stderr.log`。

## 不推荐的做法

- 不要让执行方直接在 `tasks/<task_id>/` 下运行并生成 `outputs/`。
- 不要把私有参考数据放入 `visible_data/`。
- 不要把 `std_code/` 复制给执行方。
- 不要让 judge 只支持单组数据。
- 不要只用 README 自然语言描述输出格式，应同时提供 `output_schema.json`。
- 不要为了统一模板强行改写任务说明；各类任务都应保留原任务文本，只做必要脱敏、公开路径修正或 CoT 拼接。
- 不要让 judge 从 `public/visible_data/cases.json` 反推私有 `test_cases.py`、私有参考数据或 helper 路径。
- 不要通过 `PYTHONPATH` 使用裸 `site-packages` 目录作为任务环境。
- 不要让任务执行环境和评测结果依赖不可追溯的系统 Python 全局环境。
